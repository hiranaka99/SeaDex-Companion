# SeaDex Companion 2.6.2

Faster repeat scans and better recovery from temporary SeaDex connection problems. The installed version appears as **v2.6.2** in the sidebar and mobile header.

## Changes

- Refresh known AniList titles together and reuse season information across automatic and manual matches to reduce waiting and API requests.
- Skip unnecessary automatic title searches when every season has a manual match, while preserving verified episode ranges for continuous anime.
- Keep daily season-information refreshes and earlier checks when Sonarr adds a season. New and unmatched titles still require individual title searches.
- Retry temporary SeaDex timeouts, connection failures, and rate-limit or server errors before failing a scan. Failed scans keep previous results, and error messages identify the affected catalog page and attempt.
- Preserve cancellation during requests and retry waits, along with existing AniList request pacing and rate-limit backoff.
- Retain the qBittorrent session fixes from 2.6.1.

## Validation

- All 235 automated tests passed, including batching, shared cache expiry, newly linked sequels, cancellation, manual continuous-season episode ranges, catalog retries, and qBittorrent session regressions.
- Server and frontend production builds passed.
- Browser workflow checks passed, including the installed version, scan cancellation, matching corrections, download workflows, configuration, and responsive layouts.
- A controlled 100-title fixture refreshed known AniList metadata in four requests and made no additional AniList requests on its next scan, while retaining existing request pacing.

Integration checks use isolated fixtures rather than live Sonarr, AniList, SeaDex, or qBittorrent services.

## Updating

After the release images are published, use `hiranaka/seadex-companion:2.6.2`, `:2.6`, or `:latest`. Images support Linux amd64 and arm64.

```bash
docker compose pull
docker compose up -d
```

Recreate the container to apply the update. Existing settings, manual matches, exclusions, and review history are retained. Scan improvements apply automatically; no configuration changes are needed. Scan duration still depends on library size, how much information needs refreshing, and upstream response times.
