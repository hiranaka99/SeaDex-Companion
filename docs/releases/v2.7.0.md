# SeaDex Companion 2.7.0

Usenet downloads. SeaDex Companion can now acquire releases through SABnzbd in addition to qBittorrent, discover what the public Usenet sources carry, and keep both protocols under the same review and control workflow. Torrent downloads continue to work exactly as before.

## Usenet downloads

- Choose **Torrents only**, **Usenet only**, or **Let me choose per release** under **Configuration → Downloads**. Existing installations keep using torrents only until you change it.
- Connect SABnzbd with its server URL and API key, and set the Sonarr and Radarr categories SeaDex Companion should submit to. **Test connection** verifies the setup.
- Usenet sources: AnimeTosho is enabled by default and needs no account. Optionally enable AmeNZB and provide the API key from your amenzb.moe profile. Release details show whether an Usenet source exists for each release, with its size and last check, and let you re-check on demand.
- In **choose** mode, each release offers a Torrent or Usenet method; releases without a public magnet can become Usenet-only, and releases no Usenet source carries stay torrent-only.
- Bulk downloads show the Usenet method only after a provider confirms a usable NZB for every source in the selected release. **All Usenet where available** switches those releases to Usenet and keeps the others on torrents.
- Last-known Usenet availability now survives restarts. Cached results appear immediately while missing or stale information refreshes in the background, with the provider's actual last-check time and any refresh failure shown in the review.
- Manual re-checks keep the existing information visible. If a selected Usenet source becomes unavailable, the review requires a new choice or exclusion instead of silently switching it to torrents.

## What stays explicit

- Usenet sources cannot be split per episode: the whole upload is downloaded, including files beyond the selected episodes. Bulk and single reviews show exactly which extra files are known and require your acknowledgement before sending.
- Reviews deduplicate shared sources, skip downloads already queued in qBittorrent or SABnzbd, and check free space per client and destination. When a client cannot confirm space, the review says so and asks before continuing.
- If SABnzbd is asked to start a download but the connection drops before confirmation, SeaDex Companion never re-submits it automatically. The download stays listed with **Awaiting confirmation** — check SABnzbd before retrying.
- Progress, pause, resume, and removal are labeled per client. Removing from SABnzbd keeps completed downloads unless you explicitly delete files where the client allows it.
- Changing a client URL keeps the other client's downloads untouched; entries belonging to a different client URL are shown but not controlled until the URL is restored.

## Corrections

- Standard provider NZBs, including compressed files, pass validation. SABnzbd submissions use the SABnzbd-specific Sonarr and Radarr categories.
- Cancellation removes only the downloads checked in the review. Downloads added afterward are untouched, including when file deletion is selected.
- Releases with multiple sources report every failed source. Shared downloads appear on every associated season or cour, and older acquisitions remain controllable without blocking replacement releases.
- A download confirmed missing from its client can be removed from tracking without deleting files, then acquired again. Unconfirmed submissions retain their duplicate protection and do not become successful downloads just because a tracking record exists.
- Expired or consumed single-release reviews offer a fresh review before another submission. Private-only bulk reviews keep their retry control when no Usenet source is available.
- Whole-library reviews support more than 200 selections in one deduplicated plan. Background result updates preserve the reviewed selection, and paced provider checks are not cut off by a fixed aggregate timeout.
- Current scope and disk-space requirements are checked again at confirmation. Approximate sizes and unknown destination space remain unverified, and complete source manifests determine extra-file warnings.
- Rejected confirmations and recoverable ownership-write failures release operation locks. Client responses that cannot establish acceptance keep the download marked as awaiting confirmation.
- Bulk reviews use labeled release details, availability, cache status, and check times instead of dot-separated lines. Refresh failures appear as separate warning messages.
- AnimeTosho entries that were never mirrored no longer appear as **processing** indefinitely; they show that no Usenet source is available. Only recent entries still waiting for their NZB show as processing.
- When a Usenet source rate-limits requests or stops responding, background checks pause and resume automatically, and the sidebar shows when they will continue. Checks you start yourself report the pause instead of waiting.
- Background checks start with missing and upgradable releases and skip seasons and parts you excluded. Changing unrelated settings no longer restarts them.
- Large AnimeTosho batches with detailed file listings no longer fail their availability check.
- Releases without a Usenet source are re-checked less often the longer they stay unavailable, and confirmed sources are re-checked weekly. Downloads still fetch and validate the actual NZB before sending it to SABnzbd.

## Updating

Use `hiranaka/seadex-companion:2.7.0`, `:2.7`, or `:latest` when the Docker images are available for Linux amd64 and arm64.

```bash
docker compose pull
docker compose up -d
```

Your existing torrents keep their tracking information; no configuration changes are required, and nothing contacts Usenet services until you enable them.
