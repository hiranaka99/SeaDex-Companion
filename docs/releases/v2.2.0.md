# SeaDex Companion 2.2.0

Improve season matching, scoped downloads, cancellation safety, and consistency with the canonical SeaDex domain.

## Changes

- Include digitally and physically released Radarr movies without cinema dates, and preserve movie-file ownership when statistics are missing or empty.
- Prevent unmapped later seasons and uncovered multi-season catalog buckets from borrowing another season's recommendation while preserving single-bucket release-numbering fallback.
- Limit multi-season and part-sized catalog torrents to the selected season/cour files. Avoid incomplete cour selections that silently discard unidentified episodes.
- Refresh qBittorrent state before bulk submission and cancellation so externally removed torrents can be added again and newly completed torrents are not deleted using stale progress.
- Reject malformed cancellation arrays and release indices instead of widening the cancellation scope or truncating an index to another release.
- Invalidate progress after failed selected-file cleanup and retain cleanup-failure diagnostics instead of claiming the torrent was removed.
- Count failed and already-existing torrents correctly in active and recovered batch progress.
- Reject malformed request URLs without crashing the HTTP server.
- Use `seadex.moe` consistently in source labels, unavailable-release messages, history descriptions, Discord notifications, fixtures, and generated catalog links.
- Update the frontend build dependency lockfile to resolve the reported advisory.

Integration checks use isolated local fixtures, not live Sonarr, Radarr, or qBittorrent services. Docker runtime smoke checks cover Linux amd64, not arm64.

## Updating

Back up your persistent data directory before upgrading. Existing torrents remain in qBittorrent; closing the application page does not cancel an accepted bulk download job.

After image publication completes, use `hiranaka/seadex-companion:2.2.0`, `:2.2`, or `:latest`. The release workflow publishes Linux amd64 and arm64 images.

For Docker Compose deployments using a published image:

```bash
docker compose pull && docker compose up -d
```

Run a new library scan after upgrading to refresh older stored source URLs, source labels, and torrent file metadata.

When filenames cannot identify a complete target episode set, the release remains unscoped rather than silently omitting episodes. Review the displayed whole-release scope before submitting such a download.
