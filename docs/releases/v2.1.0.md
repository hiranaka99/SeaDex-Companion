# SeaDex Companion 2.1.0

Improve download reliability and simplify the application architecture while preserving existing library and download workflows.

## Changes

- Split the backend into focused modules for scanning, configuration, library integrations, download tracking, and qBittorrent operations.
- Share typed data contracts and download planning between the server and interface so estimates, upgrade eligibility, and submitted file selections agree.
- Run bulk downloads as persistent server jobs. Progress survives page navigation and reloads; jobs interrupted by a server restart are reported without automatically repeating download operations.
- Keep individual download tracking active when cards leave the page, and retry temporary job-status polling failures.
- Use stable torrent identities for cancellation and history, including when recommendations change after a new scan.
- Serialize conflicting qBittorrent operations per torrent while allowing unrelated controls and reads to continue during metadata retrieval.
- Commit settings and encrypted credentials together, and commit torrent ownership with its library associations atomically.
- Normalize saved results at storage boundaries, prevent overlapping scans, and simplify duplicated release assessment logic.
- Add regression coverage and a reusable Docker runtime smoke test.

## Validation

- All 134 automated tests passed.
- Server and frontend production builds passed, including strict unused-code checks.
- All 20 browser workflow groups passed, covering responsive layouts, configuration, downloads, cancellation, history, and recovery.
- The Linux amd64 Docker image built successfully and passed runtime checks for non-root startup, health, static assets, authentication, encrypted settings, background jobs, restart persistence, and graceful shutdown.

## Updating

Back up your persistent data directory before upgrading. Startup reads existing settings and migrates encrypted credentials into an atomic `config.json` snapshot using the existing encryption key. Torrent ownership and its associations are also stored together. Restore the backup if downgrading to an earlier storage format.

After the release workflow publishes the images, use `hiranaka/seadex-companion:2.1.0`, `:2.1`, or `:latest`. The workflow builds Linux amd64 and arm64 images.

For Docker Compose deployments using a published image:

```bash
docker compose pull && docker compose up -d
```

Existing torrents remain in qBittorrent. Closing the application page does not cancel an accepted bulk download job.
