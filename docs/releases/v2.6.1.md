# SeaDex Companion 2.6.1

Fix qBittorrent session handling that could repeatedly create sessions and log an idle browser out when SeaDex's previous session expired and authentication bypass was enabled. The installed version appears as **v2.6.1** in the sidebar and mobile header.

## Changes

- Retain replacement cookies returned by qBittorrent API responses, including successful requests allowed through authentication bypass.
- Keep multiple cookies and custom session cookie names intact without sending cookie attributes as request cookies.
- Prevent delayed responses from overwriting newer cookies or triggering unnecessary logins after another request has refreshed the session.
- Preserve shared logins, bounded authentication retries, selected-file downloads, torrent controls, and legacy endpoint fallback.

## Validation

- All 213 automated tests passed, including eight new session regressions covering repeated polling, cookie replacement, concurrent requests, downloads, and controls.
- Server and frontend production builds passed.
- Browser workflow checks passed, including the installed version in the sidebar and mobile header.

Integration and browser checks use isolated local fixtures rather than live Sonarr, AniList, SeaDex, or qBittorrent services.

## Updating

After the release workflow publishes the images, use `hiranaka/seadex-companion:2.6.1`, `:2.6`, or `:latest`. The workflow builds Linux amd64 and arm64 images.

```bash
docker compose pull && docker compose up -d
```

Recreate the SeaDex Companion container to apply the session fix. Increasing qBittorrent's session timeout does not replace this update.
