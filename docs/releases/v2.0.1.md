# SeaDex Companion 2.0.1

Fix library scans failing with HTTP 301 while loading the SeaDex catalog.

## Cause and fix

SeaDex moved its API from `https://releases.moe/api` to `https://seadex.moe/api`. The old endpoint now returns a cross-origin HTTP 301 redirect. Version 2.0.0 still requested the old endpoint, so scans failed before the Sonarr/Radarr library was loaded.

- Request the canonical SeaDex API directly.
- Generate new SeaDex entry links using `https://seadex.moe/`.
- Keep Sonarr v5 API discovery and credential-safe redirect handling unchanged.

## Validation

- Diagnosed the running 2.0.0 container over SSH: its Sonarr v5 connection test passed; its scan log identified the old SeaDex API as the failing HTTP 301 request.
- All 124 automated tests passed.
- The corrected catalog loader fetched the live SeaDex catalog: 2,914 entries, including the expected release groups and canonical entry URL for AniList 116589.

## Updating

Use `hiranaka/seadex-companion:2.0.1`, or pull and recreate the container using `latest` after image publication completes. Existing persistent data and Sonarr/Radarr settings do not need to change.

For Docker Compose deployments using a published image:

```bash
docker compose pull && docker compose up -d
```

Run a new library scan after updating to refresh stored SeaDex links.
